# 000 — Non-functional requirements

Measurable targets every feature must respect. Verified by unit and architecture tests, live checks against the running
API, and load testing done outside the repo (scripts + k6 Studio; no in-repo integration or k6 suites, plan 011).

| ID | Area | Requirement | Verified by |
|---|---|---|---|
| NFR-1 | Correctness | Zero overlapping *Scheduled* appointments per doctor and per patient, including under concurrent requests | `AppointmentServiceTests` (pre-checks), live parallel-booking check, external load test |
| NFR-2 | Latency | `GET availability` p95 < 200 ms at 50 VUs; `POST appointments` p95 < 400 ms at 20 VUs (local Docker) | external load test (k6 Studio) |
| NFR-3 | Errors | < 1 % non-4xx failures under load | external load test (k6 Studio) |
| NFR-4 | Security | All endpoints except login/refresh/health require a JWT; role policies per endpoint group; lockout after 5 failed logins | `ArchitectureTests` (controller rules), security review, live check |
| NFR-5 | Idempotency | Every POST requires `Idempotency-Key` (PUT/PATCH/DELETE are idempotent by design; read-only POSTs are `[SkipIdempotency]`); a retried request returns the original response and creates no duplicate | live check (replay, reuse 422), external load test |
| NFR-6 | Abuse | Rate limits: login 5/min/IP, writes 30/min/user, reads 300/min/user → 429 + `Retry-After` (Polly pipelines, ADR-0009) | `RateLimitPartitionKeyTests`, live check (6th login → 429) |
| NFR-7 | Resilience | DB: no retry — atomic unit of work, transient failure → 503 `SERVICE_UNAVAILABLE` + `Retry-After` (ADR-0008); SMTP calls wrapped in timeout + retry + circuit breaker; failed messages retried then dead-lettered | live check (stop Postgres → 503), unit tests on pipelines, ops runbook |
| NFR-8 | Observability | Every request traced end-to-end (API → DB → RabbitMQ → handler/job → SMTP) in Jaeger; JSON logs carry `TraceId`; metrics at `/metrics` | manual check, `operations.md` |
| NFR-9 | Privacy | No patient PII in logs or traces; fictional seed data only | code review, log grep |
| NFR-10 | Operability | `/health/live` and `/health/ready` (DB + broker); `docker compose up` brings the full system up from clean | `/verify` |
| NFR-11 | Time | All instants stored in UTC; clinic-local presentation computed server-side from the clinic's IANA zone | `DayScheduleTests` (DST case) |
