# 000 — Non-functional requirements

Measurable targets every feature must respect. Verified by integration tests and `perf/k6`.

| ID | Area | Requirement | Verified by |
|---|---|---|---|
| NFR-1 | Correctness | Zero overlapping *Scheduled* appointments per doctor and per patient, including under concurrent requests | `race-same-slot.js`, `ConcurrencyTests` |
| NFR-2 | Latency | `GET availability` p95 < 200 ms at 50 VUs; `POST appointments` p95 < 400 ms at 20 VUs (local Docker) | `load-availability.js`, `stress-booking.js` |
| NFR-3 | Errors | < 1 % non-4xx failures under load | k6 thresholds |
| NFR-4 | Security | All endpoints except login/refresh/health require a JWT; role policies per endpoint group; lockout after 5 failed logins | `AuthTests`, security review |
| NFR-5 | Idempotency | All POST/PUT/PATCH/DELETE require `Idempotency-Key`; a retried request returns the original response and creates no duplicate | `IdempotencyTests`, `idempotency-replay.js` |
| NFR-6 | Abuse | Rate limits: login 5/min/IP, writes 30/min/user, reads 300/min/user → 429 + `Retry-After` | `RateLimitTests`, `rate-limit.js` |
| NFR-7 | Resilience | Transient DB errors retried; SMTP calls wrapped in timeout + retry + circuit breaker; failed messages retried then dead-lettered | unit tests on pipelines, ops runbook |
| NFR-8 | Observability | Every request traced end-to-end (API → DB → RabbitMQ → Worker → SMTP) in Jaeger; JSON logs carry `TraceId`; metrics at `/metrics` | manual check, `operations.md` |
| NFR-9 | Privacy | No patient PII in logs or traces; fictional seed data only | code review, log grep |
| NFR-10 | Operability | `/health/live` and `/health/ready` (DB + broker); `docker compose up` brings the full system up from clean | `/verify` |
| NFR-11 | Time | All instants stored in UTC; clinic-local presentation computed server-side from the clinic's IANA zone | `AvailabilityPolicyTests` (DST case) |
